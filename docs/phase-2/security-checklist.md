# Phase 2 security checklist update

**[Security Engineer]** 18 Nov 2026. Changes to [`../phase-1b/security-checklist.md`](../phase-1b/security-checklist.md); rows not listed are unchanged.

| Control | Status | Evidence |
| --- | --- | --- |
| Report access | ✅ | Snapshots, artefacts and templates: read by compliance, CEO, credit and auditor; create and generate by compliance and CEO only; suppliers and buyers 403 (TC-P2-RPT-06). Every download is audited with the file's SHA-256 and served `no-store`, `nosniff` |
| Report integrity | ✅ | `report_snapshot` and `report_artifact` have SELECT and INSERT grants only (UPDATE/DELETE/TRUNCATE revoked). Each stores a SHA-256; generation refuses if regenerated bytes differ (`NOT_REPRODUCIBLE`) or the snapshot hash no longer verifies (`SNAPSHOT_TAMPERED`). The append-only check is in TC-P2-RPT-01 using the app's own database role |
| Template changes | ✅ | A new CBK/CRB/lender template only takes effect after maker-checker (compliance proposes, the CEO approves); audited (TC-P2-RPT-05) |
| CSV injection | ✅ | Every cell passes `csvCell`: values starting `=`, `+`, `-`, `@`, tab or CR are prefixed with `'` (plain negative numbers excepted); quotes escaped |
| PII in CRB files | ✅ / 🟡 | Only company identifiers (KRA PIN, registration number); no personal IDs. Borrowers without CRB consent excluded by default (D-45). Identifiers are not logged. 🟡 The official spec may need directors' IDs, which would need decrypting into the file: design review then |
| Report artefacts at rest | 🟡 | Stored as `bytea` in Postgres, protected by database access and disk encryption only. **S-09:** encrypt artefacts with `STORAGE_ENCRYPTION_KEY` like uploaded documents before go-live |
| Reconciliation | ✅ | Baseline and every break resolution are maker-checker (a second ops user); the maker cannot approve (four-eyes); audited. Unexplained breaks alert ops and compliance |
| Recourse | ✅ | Now maker-checker with step-up (D-41); supplier notified only after approval |
| Collections policy | ✅ | Validated (400 on bad values) and maker-checker (credit proposes, CEO approves) |
| Adapter secrets | ✅ | New secrets (`XERO_ACCESS_TOKEN`, `HUBSPOT_PRIVATE_APP_TOKEN`, `SITE_D1_API_TOKEN`) come from env only; `.env.example` has empty values. Sandbox adapters refuse to start a call without credentials; `live` refused outside production and `mock` refused in production |
| D1 lead reader | ✅ | Only parameterised `SELECT`s on `call_requests` / `data_requests` (test asserts no other SQL). Token should be scoped to D1 read on that database only (Q-F). The site Worker is not changed |
| CRM data sharing | ✅ / 🟡 | Only buyer leads with a privacy-notice acceptance; no marketing opt-in; erasure requests skipped, and later erasures flagged `erasure_pending`. 🟡 HubSpot needs a data-processing agreement and a cross-border transfer assessment before sandbox or live use |
| Accounting push | ✅ | Idempotency key per day; unbalanced journals refused; journals created as DRAFT in Xero so the accountant posts them |
| Dev endpoints | ✅ | New `dev/bank/ingest-statement` and `dev/jobs/daily` live in the dev module, mounted only with `DEV_IDP_ENABLED=true` outside staging/production |
| Public licence wording | ✅ | Outside production the CBK statement always says "not yet licensed" with a DEMO marker, even if test data holds a licence number (D-42) |
| Dependencies | ✅ | `npm audit --omit=dev`: 0 vulnerabilities |
